# 큰 방향 전환과 문서 구조 개편

목적이나 제품 방향이 바뀌는 것과 같은 내용을 더 읽기 쉽게 재배치하는 것을 구별한다. 개편은 확인한 읽기 문제와 요구 범위에 맞게 작게 수행한다. 새 구조가 보기 좋아 보인다는 이유만으로 기존 문서·이력·사용자 문장을 전체 재작성하지 않는다.

## 행동 선택

| 신호 | 선택 |
| --- | --- |
| 같은 주제에 확인한 사실이 추가됨 | 기존 문단 수정 |
| 별도의 질문에 답하고 충분한 맥락·근거가 있음 | 상세 문서 분리 + 상위 요약 |
| 동일 대상·범위가 중복되거나 짧은 글이 맥락에 의존함 | 통합 후보 검토 |
| 이름만 부정확하거나 변경됨 | 본문 재생성 대신 이력 보존 이동 검토 |
| 제품 목적·설계 선택이 달라짐 | 새 결정과 대체 관계 + 현재 설명 갱신 |
| 사실 오류가 밝혀짐 | 근거 있는 정정; 의미 있는 판단 변화가 없으면 새 결정은 만들지 않음 |
| 일지가 너무 많아 찾기 어려움 | 원래 URL을 보존하는 월/연도/주제 색인 검토 |

분리 전에 목적지의 기존 문서를 읽는다. 새 문서가 독립적으로 읽히는지, 요약과 상세가 같은 사실을 말하는지 확인한다. 통합 시 같은 내용의 중복과 서로 다른 시기의 상태 차이를 구별한다.

## 먼저 완성할 개편안

다음 정보를 실제 제목·읽은 리비전·근거로 채운다. 사용자 승인이 필요한 작업이면 추상적인 허락을 먼저 묻지 않고 이 안을 검토 가능한 상태로 만든다. 현재 요청이 이미 해당 변경을 허용하면 불필요하게 다시 허락받지 않는다. 별도로 적용되는 파괴적 작업·권한 규칙은 유지한다.

| 대상 | 기록할 사항 |
| --- | --- |
| 이유와 범위 | 찾기 어려운 내용, 중복, 새 요구와 개편 후 읽기 경로 |
| 대응표 | 이전 제목/문단 → 이후 제목/문단, 유지·수정·분리·통합·이동 구분 |
| 보존 | 각 고유 설명·실패·인용·출처의 새 위치, 이전 URL과 이력 보존 방법 |
| 영향 | 관련 링크·역링크·목차·분류·둘러보기, 프로젝트 설정·저널·대기 기록 |
| 순서 | 목적지 확보 → 본문 검증 → 상위 요약/연결 → 후속 링크 확인 |
| 중단/복구 | 단계별 확인 결과·리비전, 실패 시 다시 읽을 문서와 재개 지점 |

이 계획은 현재 `edits`/`deferred` JSON에 임의 새 필드를 추가하는 방식으로 전달하지 않는다. 수동 개편안은 Markdown 등 별도 검토 자료로 남기고, 자동 계획에는 지원되는 개별 문단 수정만 넣는다.

## 적용과 확인

1. 최신 원문·이력·역링크를 읽고 사람이 바꾼 부분과 자동 관리 부분을 확인한다. 잘린 원문으로 개편안을 확정하지 않는다.
2. 구조 변경에 필요한 범위의 복구 자료를 확보한다. 살아 있는 DB를 임의 파일 복사로 백업했다고 간주하지 않고 기존 백업 절차를 따른다.
3. 분리 목적지에 필요한 설명과 출처를 먼저 확보한다. 부분 저장 실패 시 원래 문서를 유지하고 전체 완료로 보고하지 않는다.
4. 상위 문서는 핵심 요약과 목적지 링크를 갖게 한다. 상세에는 상위·관련 일지·결정으로 돌아가는 연결을 둔다.
5. 제목 변경은 이력 보존을 지원하는 정식 이동 경로를 확인한다. MCP `wiki_save`만으로 새 페이지 복사+옛 페이지 비우기를 수행해 정식 이동처럼 처리하지 않는다. 이동 미지원이면 기존 제목을 유지하고 계획을 남긴다.
6. 리비전 충돌이나 사람 수정이 있으면 그 범위만 다시 읽고 병합한다. 과거 백업 전체를 덮어써 복구하지 않는다. 저장 결과가 불명확하면 실제 원문·이력을 먼저 확인한다.
7. 이전 링크, 상위→상세→상위 이동, 근거·이력, 주요 역링크와 설정/저널 대응을 확인한다. 리다이렉트가 있는 경우 반복·연쇄 오류도 확인한다. 사용량 합계가 문서 복제로 증가하지 않았는지 확인한다.

기존 결정이 새 결정으로 대체되면 양쪽 문서에서 관계·적용 시점·전환 미완료 범위를 알 수 있게 한다. 이전 문서를 읽지 못했거나 수정 권한이 없으면 새 문서에서 확인된 관계를 밝히고 반대쪽 수정은 보류한다.

## 현 실행기 한계

현재 `project_wiki.py`는 관리 문단의 생성·교체, 링크·최근 일지 연결을 한다. 문서 이동/삭제/이력 병합, 자동 블록 key 변경·재배치, 프로젝트 이름 변경에 따른 모든 경로·상태 마이그레이션을 지원하지 않는다. 여러 문서 저장을 한 트랜잭션으로 묶지도 않는다.

따라서 기존 key를 새 key로 바꿔 중복 블록을 만들지 않는다. 문단 재배치·문서 이동·기존 영역 제거가 필요하면 자동 모드에서 그 작업을 deferred에 구체적으로 남긴다. 분리할 상세 문서와 원래 문단의 요약을 지원 범위에서 생성·교체할 수 있더라도, 기존 고유 내용과 근거가 보존되는지 먼저 확인한다.

이 지침은 큰 개편을 판단·설계·검토하는 능력을 제공한다. 도구가 지원하지 않는 작업까지 자동 적용할 수 있다는 약속은 아니다.
