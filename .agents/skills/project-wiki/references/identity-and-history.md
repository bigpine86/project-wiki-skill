# 식별자·채번·시간의 장기 유지

## 번호마다 역할을 하나씩 둔다

| 대상 | 식별 기준 | 바뀔 때의 처리 |
| --- | --- | --- |
| 프로젝트 | 등록한 `project_id` | 이름·폴더 변경만으로 새 프로젝트로 만들지 않음. 분기된 별도 제품이면 새 ID와 원래 프로젝트 연결을 검토 |
| 문서 | 실제 위키 제목·역할·관련 프로젝트 | 제목이 현 저장소의 주소다. 임의의 문서 UUID가 이미 존재한다고 가정하지 않음 |
| 자동 문단 | 프로젝트 ID와 기존 문서 안의 안정적인 key | 제목 표시만 바뀌어도 key를 불필요하게 변경하지 않음. 문서 이동 시 저널의 제목+key 대응도 검토 |
| 일지 | 프로젝트와 ISO 날짜 `YYYY-MM-DD` | 같은 날 여러 입력은 주제로 묶음. 재시도로 날짜 변경 금지 |
| 커밋 근거 | 저장소와 전체 SHA | 짧은 SHA는 표시용. amend/rebase는 새 SHA이나 같은 사건인지 별도로 판단 |
| 커밋 없는 입력 | 최초 접수한 수동 기록 ID | 재시도는 동일 ID. 원문 수정만으로 기존 요청을 정정한 것으로 보지 않음 |
| 중요 결정 | 기존 문서 + 선택적으로 프로젝트별 `ADR-0001` | 번호는 발급 순서. 날짜·주제·문서 위치와 분리. 대체·폐기되어도 재사용 금지 |
| 위키 수정 | 문서의 실제 리비전 | 저장·충돌·이력 근거. 개발 버전이나 결정 번호로 쓰지 않음 |
| 모델 사용량 | 도구/세션/요청 식별자와 집계 구간 | 커밋·문서 복제와 별개로 중복 제거. 근거가 없으면 완전 집계로 보지 않음 |

목차의 1, 2.1 같은 숫자를 수동 영구 ID로 삼지 않는다. 섹션 링크도 제목·문법·엔진에 따라 달라질 수 있으므로 개편 후 실제 연결을 확인한다. 문서 주소 전체를 채번 순서로 구성하거나 일지에 전역 순번을 매기지 않는다.

## 결정 번호를 도입하는 경우

기존 의미 있는 제목을 유지한다. 예를 들어 `의사결정/프로젝트명/저장 방식 선택`에 `ADR-0007`을 표시할 수 있다. 기존 문서 전부를 번호가 포함된 URL로 이동하지 않는다. 이미 번호 규칙이 있으면 새 규칙보다 그것을 우선한다.

번호가 필요한 새 결정에는 다음 원칙을 적용한다.

1. 같은 결정을 다룬 문서·번호가 이미 있는지 확인한다. 같은 근거를 다시 보았다는 이유로 새 번호를 발급하지 않는다.
2. 프로젝트의 권위 있는 결정 목록에서 할당 번호·대상 문서·날짜·상태·대체 관계를 확인한다. 검색 일부나 모델 기억으로 최댓값을 정하지 않는다.
3. 동시 편집에 안전한 목록 갱신과 저장 확인이 가능한 경우에만 다음 번호를 확정한다. 실패·부분 성공이면 먼저 실제 목록을 다시 읽는다. 현 실행기는 이 할당을 자동 보장하지 않는다.
4. 읽기 범위가 부족하거나 충돌하면 번호를 미배정으로 두고 주제 제목으로 기록한다. 날짜를 끼워 넣거나 임의의 큰 숫자를 만들어 충돌을 회피하지 않는다.
5. 한번 할당한 번호는 취소·통합·대체되어도 유지한다. 같은 번호에 다른 결정을 넣지 않는다. 나중에 발견한 과거 결정은 다음 번호와 실제 결정일을 기록하며 기존 번호를 재정렬하지 않는다.

공유 목록의 자동 생성·원자적 할당은 별도 구현 대상이다. 여러 PC에서 로컬 파일의 카운터만 각각 올리는 방식으로 전역 번호를 약속하지 않는다. 문서 이동·프로젝트 분리 시 기존 번호의 프로젝트 범위와 이전 링크를 보존한다.

## 날짜와 역사

일지 제목의 날짜, 실제 작업·결정 시각, 원본 자료 시각, 위키에 기록한 시각을 구별한다. 현재 실행기는 커미터 시각을 Asia/Seoul로 바꿔 자동 일지를 정하고 수동 입력은 지정 날짜를 따른다. 재시도 시 오늘 날짜로 바꾸지 않는다. 다른 시간대 규칙을 적용하려면 기존 자동 날짜 규칙과 호환성을 먼저 검토한다.

여러 날의 대화가 한 커밋에 묶이면 확인된 작업 구간을 본문에 표시한다. 날짜별 재구성이 필요하면 기존 근거와 함께 수동 계획을 준비하고, 실행기가 대화를 알아서 날짜별로 나눈다고 설명하지 않는다. 출처 없이 과거 날짜의 일지를 만들지 않는다.

늦게 발견한 과거 자료는 해당 날짜의 사실을 보충할 수 있다. 당시 판단은 그대로 두고 후대의 확인·오류 정정은 그 확인 시점을 명시한다. 일지를 개선할 수 있지만 과거의 실패나 당시의 미완료 상태를 지금 성공했다는 이유로 제거하지 않는다.

## 사용량의 시간과 합계

토큰 이벤트 발생일과 연결된 커밋의 일지 날짜가 다를 수 있다. 일/월 사용량은 어느 시간대를 기준으로 어떤 요청을 포함했는지 명시한다. 일지에 표시한 커밋 귀속량을 곧바로 그날의 실제 소비량으로 해석하지 않는다.

개발 사용량·위키 작성 사용량은 각각 원본 요청의 중복 없는 집계에서 도출한다. 일지·월간 요약·프로젝트 총계는 같은 수치의 다른 보기이며 서로 더하지 않는다. 문서 재구성이나 결정 번호 추가는 개발 사용량 증가가 아니다. [세부 기준](usage-recording.md)
