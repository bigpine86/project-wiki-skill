# 프로젝트 생애주기별 작성 기준

첫 등록·방향 전환·중단/재개를 다루는 수동 작업의 상세 참조다. 자동 계획은 [편집 기준](editing-rules.md)에 정리한 핵심만 전달받는다. 현재 설명, 당시 일지, 중요한 판단, 원본 근거를 연결한다. 공개 백과사전의 패턴을 개인 위키에 적용하며 외부 위키 게시를 뜻하지 않는다.

## 입력을 문서 행동으로 바꾸기

먼저 기존 개요·대상 일지·관련 문서와 근거 범위를 확인한다. 기존 문서가 읽기 한도에서 빠진 것은 없는 문서라는 뜻이 아니다. 다음 상황을 판단하되 출력에 새 mode 필드를 만들지 않는다.

| 상황 | 우선 행동 | 보존할 것 |
| --- | --- | --- |
| 처음 등록 | 짧은 소개, 시작 배경, 확인된 상태, 저장소, 첫 일지 연결 | 실제 시작일과 등록일의 차이, 미확인 범위 |
| 진행 중인 프로젝트를 뒤늦게 등록 | 현재 개요와 확인한 이정표부터 정리 | 과거 자료의 빈 구간; 역사를 추측해 채우지 않음 |
| 일상 개발·조사 | 기존 날짜의 같은 주제에 새 결과를 합치고 현재 설명의 해당 부분만 수정 | 원래 문제·실패·선택 이유·커밋 근거 |
| 여러 날 계속하는 작업 | 날짜별 진전을 각 일지에 두고 동일한 상세 주제로 연결 | 각 날짜의 상태와 미완료 범위 |
| 큰 방향 변경 | 변경 이유·대안·채택 시점, 이전/새 결정 관계, 전환 단계 | 이전 결정의 당시 타당성; 채택과 구현 완료의 차이 |
| 분리·통합·이름 변경 | 구조 개편 계획과 영향 문서를 준비; 지원 범위 안에서 적용 | 원문 출처·이력·이전 링크·사람 수정 |
| 사실 오류 정정 | 오류 지점과 새 근거를 명시하고 현재 글·관련 요약을 바로잡음 | 중요한 판단에 영향을 준 오류의 정정 시점과 이유 |
| 출시·중단·재개·종료 | 확인 시점의 상태·마지막 결과·미해결 사항·후속 연결 | 이전 일지와 결정; 미확인 출시/재개를 만들어내지 않음 |

새 사실이 없으면 기존 글을 그대로 둔다. 매 커밋마다 모든 문서를 손보거나 똑같은 상태 요약을 반복하지 않는다. 입력이 일상 작업인지 큰 전환인지 불명확하면 확인 가능한 좁은 사실부터 기록하고 전환의 의미를 상상하지 않는다.

## 처음 소개와 목차

처음 읽는 사람이 개요만으로 대상·필요·현재 범위를 이해할 수 있게 쓴다. 짧은 소개 다음에 필요한 배경·기능/구조·운영·개발 흐름을 배치한다. 빈 섹션을 채우는 방식으로 시작하지 않는다.

- 소개: 무엇이며 누구의 어떤 문제를 해결하는가. 홍보 문구나 설명 없는 링크 목록으로 대신하지 않는다.
- 시작 배경: 어떤 불편·요구에서 시작했고 왜 이 접근을 골랐는가. 사용자 발언과 관찰 근거를 구별한다.
- 현재 범위: 확인한 기준 시점·기능·제약·계획. 선택한 방향과 동작하는 기능을 구분한다.
- 기본 정보: 실제 저장소·실행 안내·상태·관련 문서. 존재하지 않는 주소·버전·시작일은 만들지 않는다.
- 목차: 주제에 필요한 질문에 맞춘다. 라이브러리는 사용 범위/인터페이스, 도구는 사용 흐름/제약, 연구는 질문/방법/검증 중심일 수 있다. 모든 프로젝트에 같은 장을 강제하지 않는다.

다음은 **가상 기획 단계 예시**이며 현재 프로젝트의 사실이 아니다.

> 실험 노트는 개인 연구자가 실험 조건과 결과를 다시 찾기 쉽게 연결하려는 도구다. 파일과 대화에 흩어진 기록을 함께 읽기 어렵다는 문제에서 시작했다. 현재는 기록 항목과 저장 방식을 검토하는 단계이며, 자동 수집과 공유 기능은 구현 여부가 확인되지 않았다.

아이디어만 있어도 소개 초안은 쓸 수 있다. 현 실행기의 overview/detail 저장에는 기준 브랜치 자료와 코드 근거 검사가 필요하다. 근거로 사용할 추적된 README·설계 파일이 있으면 수동 입력의 `--file`로 제공하고, 없으면 소개 초안을 남긴다. 이 검사를 우회하려고 사용자 발언의 role을 code로 바꾸거나 구현 자료를 만들어내지 않는다. 확인된 초기 논의는 일지에 기록할 수 있다.

## 현재 설명·당시 기록·근거의 관계

현재 설명은 기준 브랜치에서 확인한 동작을 나타낸다. 일지는 당시 문제 → 시도 → 선택 이유 → 결과와 남은 일을 보존한다. 중요한 결정은 그 이유와 상태를 설명한다. 위키 수정 이력은 글을 고친 이력이며 개발 일지를 대신하지 않는다.

같은 날 여러 커밋이 같은 문제를 해결했다면 하나의 주제 흐름에 합치고 커밋은 근거로 연결한다. 서로 다른 실패나 선택을 없애지 않는다. 커밋이 없는 조사도 실제 날짜와 출처가 있으면 기록한다. 변경 파일 수·커밋 수를 작업 가치나 토큰 사용량으로 바꾸지 않는다.

현재 자동 일지 날짜는 커미터 시각을 Asia/Seoul로 환산한 날짜다. 실제 작업일과 다르면 원본 작업 시각을 별도로 밝힌다. 늦게 처리한 입력은 본래 날짜에 보충하고 지금의 소개를 과거 상태로 되돌리지 않는다. 현재 설명/상세 수정은 `current_allowed`와 기존 코드 근거 규칙을 그대로 따른다.

## 중요한 결정과 방향 변경

이후 구조·운영·선택에 영향을 주고 독립적으로 다시 읽을 가치가 있는 판단만 별도 결정 문서로 만든다. 문제/조건, 검토한 대안, 선택과 이유, 상태·적용 시점, 장단점과 확인 결과를 필요한 만큼 설명한다.

기존 결정을 바꾸면 이전 문서의 이유를 새 이유로 대체하지 않는다. 새 결정과 이전 결정을 연결하고, 이전 판단이 대체되었는지·일부만 유효한지·아직 전환 중인지 구분한다. 이전 문서를 읽지 못하면 그 문서의 상태를 수정하지 말고 확인한 새 판단과 남은 연결 작업을 기록한다. 검토/채택/구현/배포는 별개 상태다.

단순 사실 정정은 새로운 아키텍처 결정을 만들 이유가 아니다. 오탈자는 바로잡고, 결과나 결정 이유를 바꾸는 정정은 근거와 시점을 남긴다. 당시의 실제 판단을 현재의 평가로 소급 대체하지 않는다.

## 글이 커질 때

요약은 전체를 이해하게 하고 상세 문서는 독립적인 질문에 답한다. 분리 판단은 반복 참조, 독립성, 서로 다른 읽기 목적, 유지보수 중복과 읽기 불편을 근거로 한다. 분량 기준 하나로 자동 분리하지 않는다.

분리 시 상위에는 요약과 상세 링크를, 하위에는 맥락과 상위 링크를 남긴다. 중복·짧은 글·맥락 의존성이 크면 통합을 검토한다. 기존 출처·고유한 설명을 옮길 곳 없이 제거하지 않는다. 문서 제목·자동 블록 key를 바꾸거나 사람이 고친 영역을 건드리는 개편은 일상 자동 수정으로 숨기지 않는다.

월/연도별 색인이나 발전 과정 요약은 탐색상 필요할 때 추가한다. 기존 일지 URL은 유지하고 색인에서 연결한다. ‘최근 일지’에서 빠져도 전체 기록에서 찾을 수 있어야 한다. 릴리스·방향 전환·재개 시 관련 소개/상세/링크의 낡은 내용을 점검한다. 이 기준은 주기 실행을 설치하지 않는다.

## 식별자와 사용량

목차 번호는 표시 순서다. 안정적인 프로젝트 ID, 전체 커밋 SHA, 수동 입력 ID, 문서 제목, 위키 리비전과 혼동하지 않는다. 기존 key·ID·URL을 보존한다. 중요한 결정에 ADR 번호를 사용하면 프로젝트 안에서 증가시키고 재사용하지 않는다. 읽은 문서 일부의 최댓값만으로 새 번호를 확정하지 않는다. 현 실행기에는 원자적인 ADR 번호 할당기가 없으므로 자동 계획에서 새 번호를 발급하지 않는다.

개발 토큰과 위키 작성 토큰은 구분한다. 문서가 이동·분리되거나 동일 커밋을 재처리했다고 사용량을 새로 더하지 않는다. 계획 모델은 검증된 sources의 수치를 설명할 뿐 합계·비용을 계산하지 않는다. 누락은 미확인으로 유지한다.

## 실제 지원 범위와 완료 확인

자동 모드에서는 함께 제공된 context만 읽고 `edits`/`deferred`로 관리 문단의 생성·수정과 링크를 제안한다. 역할·제목 범위, 정확한 인용, 사람 수정 보존을 유지한다. 문서 이동/삭제/이력 병합, ADR 자동 채번, 여러 날 자료의 자동 재분배는 지원하지 않는다. 토큰 집계는 별도 결정적 실행기가 담당한다. 필요한 미지원 작업만 deferred에 적고 안전한 일지 기록은 계속한다.

수동으로 큰 개편을 다룰 때는 [구조 개편](restructuring.md), 채번·날짜를 다룰 때는 [식별자와 시간](identity-and-history.md), 사용량을 다룰 때는 [사용량 기준](usage-recording.md)을 읽는다. 자동 모드에서는 이 파일들을 추가로 읽으려 도구를 호출하지 않는다.

완료 보고는 실제로 작성·수정한 문서와 확인한 근거, 보류한 작업을 구별한다. 초안은 저장으로, 문서 저장은 코드 배포로, 확인한 일부 기록은 완전한 역사로 바꾸지 않는다.
