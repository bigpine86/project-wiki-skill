# AI 사용량 수집과 조회

실행기가 개발 사용량과 위키 작성 사용량을 계산한다. 집계·동기화·사용량 문단 갱신에는 모델을 호출하지 않는다. 모든 수치는 **관측된 부분 합계**다.

## 수집과 귀속

- 개발: 커밋 또는 Entire 메타데이터에 연결된 정확한 Codex 세션을 읽는다. 세션 ID·작업 폴더·요청 ID를 확인한다. 요청 시점의 모델과 `token_usage_record` 수치를 저장한다.
- 위키 작성: 기존 생성 호출의 `turn.completed.usage`를 읽는다. 고유 호출 ID, 생성 완료/실패/시간 초과, 미리보기/저장 계획, 시도 번호를 함께 남긴다. 생성 완료가 위키 저장 완료를 뜻하지는 않는다. 기존 기록에서 알 수 없는 상태는 미확인이다.
- 총량은 입력+출력이다. 캐시 입력과 추론 출력은 부분집합이므로 다시 더하지 않는다. CLI 요약을 API 요청 한 번으로 가정하지 않는다. 제공되지 않은 모델·수치·요청 수는 미확인이다.
- 누적 `token_count`와 Entire 누적값은 합산하지 않는다. 요청별 근거가 없는 로그와 다른 도구는 자동 합계에서 제외한다. 미수집은 0이 아니다.

커밋 시작 경계는 **세션마다** 이전 커밋 관측 시각으로 계산한다. 첫 구간은 부모 커밋 시각을 사용한다. 경계를 확인할 수 없으면 세션 전체를 첫 커밋에 넣지 않는다. 구형 공통 경계는 로컬 입력 기록으로 보완한 뒤 중앙에 보낸다.

요청 시각과 turn 시작이 정확히 한 구간에 들어갈 때만 커밋에 연결한다. 경계를 넘거나 브랜치/amend 구간이 겹치면 귀속 미확인으로 둔다. 관측 합계에는 한 번 포함한다. 이는 연결 기준이며 해당 커밋만을 위해 소비한 양을 증명하지 않는다.

같은 요청 ID는 한 번 센다. 수치·모델·시각·프로젝트가 충돌하면 덮어쓰거나 두 번 더하지 않고 제외한다. 중앙 충돌은 자동 해결하지 않는다. 원본과 제출 경로를 확인한다. 저장 재시도는 저장된 생성 계획을 재사용한다. 명시적 재생성은 별도 호출로 기록한다.

## 조회와 연결

```sh
# 로컬 조회 / 연결된 세션 새로고침
python3 scripts/project_wiki.py usage
python3 scripts/project_wiki.py usage --refresh

# 중앙 전송. 성공하면 이 프로젝트의 자동 중앙 동기화를 활성화한다.
python3 scripts/project_wiki.py usage --refresh --sync

# 중앙 조회만 수행
python3 scripts/project_wiki.py usage --central

# 지정 일지와 내용이 달라진 기존 관리 일지의 사용량 문단 갱신
python3 scripts/project_wiki.py usage --refresh --date 2026-10-29 --apply
```

위키 서버와 MCP 어댑터 모두 `wiki_usage_sync`/`wiki_usage_read` 지원 버전이어야 한다. 프로젝트 개요와 일지에는 `/personal_usage/<project_id>` 링크를 둔다. 상세 화면에서 월을 선택하고 기간·모델·커밋 합계, 요청 근거, 생성 상태와 수집 누락을 확인한다.

`usage_central=true`이면 중앙 원장의 합계로 요약한다. 한 PC의 로컬 합계로 덮어쓰지 않는다. 전송 실패는 로컬 대기로 남는다. 같은 명령을 다시 실행할 수 있다. 기존 MCP의 loopback 제한과 프로젝트 문서 ACL을 유지한다.

project/day/month/model/commit은 같은 요청의 다른 보기다. 이 표들을 서로 더하지 않는다. 날짜·월 표는 발생 시각의 Asia/Seoul 기준이다. 일지와 생성 호출 표는 연결 날짜 기준이다. 늦게 수집한 요청으로 값이 달라지면 기존 관리 일지도 모델 없이 갱신한다. 변하지 않은 과거 문단은 다시 읽거나 저장하지 않는다. 사람이 수정한 문단은 보존하고 검토 대상으로 남기므로 상세 조회와 일지 값이 다를 수 있다.

## 보존과 한계

로컬 원장은 Git 관리 폴더의 `devlog-wiki/usage/`에 있다. 중앙 원장은 위키 DB의 `personal_usage`에 저장한다. 요청 식별자·모델·시각·수치·연결 정보만 보낸다. 대화·추론 내용·인증 값은 넣지 않는다. 생성 CLI 임시 출력은 수치 추출 후 제거한다.

위키의 `scripts/backup_local.py`는 DB와 함께 로컬 원장·대기 입력·편집 기준을 비공개 백업한다. 다른 개발 저장소는 `--state-repo /path/to/project`로 포함한다. 쓰는 중인 작업이 있으면 백업을 거부한다. `--restore-state <백업/devlog-wiki> --repo <대상>`은 해시를 확인하고 빈 상태 폴더에만 복원한다. DB와 편집 상태는 같은 시점의 백업을 사용한다. GitHub 소스 푸시는 이 데이터의 백업이 아니다.

여러 PC가 같은 중앙 서버에 제출한 ID는 중복 집계하지 않는다. 원격 접속·자동 전송 데몬·모든 과거 대화 역수집·정확한 청구액 계산은 제공하지 않는다. 여러 PC 연결은 별도 보안 연결 설정이 필요하다. 프로젝트 ID와 개요 연결은 자동 변경하지 않는다.

모델은 `ai-usage` 문단이나 합계를 작성하지 않는다. 원장/API를 수정할 때만 [저장 설계](../../../../docs/USAGE_STORAGE_DESIGN.md)를 읽는다.
