# AI 사용량 자동 수집과 집계

`mode=project` 실행기는 개발 사용량과 위키 작성 사용량을 숫자로 수집한다. 계산에 모델을 추가 호출하지 않는다. 일지에는 짧은 합계와 접힌 커밋별 내역을 저장한다. 모든 수치는 **관측된 부분 합계**다.

## 수집 범위

- 개발: 커밋을 실행한 정확한 Codex 세션 또는 Entire 메타데이터에 연결된 세션의 로컬 JSONL을 읽는다. 세션 ID와 작업 폴더를 확인한다. `token_usage_record`의 요청 ID와 수치를 사용한다.
- 위키 작성: 기존 Codex 생성 호출의 JSON 출력에서 `turn.completed.usage`를 읽는다. 실행마다 호출 식별자와 사용량 수집 여부를 남긴다. 성공·실패·미리보기·재생성의 명시적 상태는 아직 저장하지 않는다. 사용량 출력이 없으면 미수집이며, 이것만으로 생성 실패를 뜻하지는 않는다.
- 입력·출력·캐시·제공된 추론 토큰을 보관한다. 총량은 입력+출력이다. 캐시 입력과 추론 출력은 부분집합이므로 다시 더하지 않는다.
- 개발 모델은 요청 시점의 turn context에서 확인한다. CLI가 모델을 제공하지 않는 위키 작성은 모델 미확인이다. 개발은 요청 ID 수, 위키 작성은 실행기 호출 수를 확인할 수 있다. CLI 요약을 API 요청 한 번으로 가정하지 않는다.
- Entire의 누적 token_usage와 Codex의 누적 token_count는 합산하지 않는다. 요청별 근거가 없는 형식, 누적값만 있는 기록, 다른 도구는 현재 자동 합계에서 제외한다. 수동으로 검증한 자료는 출처별로 별도 설명할 수 있다.

## 커밋 경계와 중복 방지

같은 요청 ID는 한 번만 저장한다. 같은 ID의 수치가 충돌하면 그 요청을 합계에서 제외하고 검토 대상으로 표시한다. 저장 재시도는 기존 생성 결과를 사용하므로 새 모델 사용량을 만들지 않는다. 모델을 다시 호출했다면 별도의 위키 작성 사용량이다.

자동 귀속은 이전에 관측한 동일 세션의 커밋 시각부터 현재 커밋 관측 시각까지의 구간을 사용한다. 첫 수집은 부모 커밋 시각을 경계로 사용한다. 시작 경계를 확인하지 못하면 세션 전체를 첫 커밋에 넣지 않는다. 구간은 작업과 연결한 기준이며 그 커밋만을 위해 소비한 양을 증명하지 않는다.

현재 여러 세션을 한 커밋에 연결하면 공통 시작 경계를 사용한다. 세션마다 이전 경계가 다른 경우 일부 요청이 귀속 미확인으로 남는 사례를 확인했다. 세션별 경계 보완 전에는 이를 정확한 다중 세션 귀속으로 설명하지 않는다.

요청이 기록된 시각이 구간 안에 있고 해당 turn도 경계 이후 시작했을 때만 커밋에 연결한다. turn이 커밋 경계를 넘거나 여러 브랜치/amend 구간이 겹치면 귀속 미확인으로 둔다. 전체 관측 합계에는 한 번만 포함한다. 다음 커밋 수집이나 명시적 새로고침에서 늦게 기록된 요청을 다시 확인한다. 원래 시각이 이전 구간에 속하면 이전 커밋에 연결할 수 있다. 완료 시각만으로 이전 커밋에 속한다고 추측하지 않는다.

## 조회와 갱신

```sh
# 로컬 집계 조회. 모델 호출과 위키 저장 없음.
python3 scripts/project_wiki.py usage

# 기존 기록에 연결된 정확한 세션을 다시 읽는다.
python3 scripts/project_wiki.py usage --refresh

# 지정 날짜의 AI 사용량 문단만 저장한다. 모델 호출 없음.
python3 scripts/project_wiki.py usage --refresh --date 2026-10-29 --apply
```

`totals`의 project/day/month/model/commit은 같은 원본 요청의 다른 보기다. 이 요약끼리 더하지 않는다. day/month는 이벤트 발생일의 Asia/Seoul 기준이다. 일지 표시는 커밋에 연결한 날짜 기준이므로 실제 그날 소비량과 다를 수 있다. `commit:unattributed`는 귀속 미확인이다. 누락·충돌 정보와 호출별 수집 여부도 보고서에 포함된다.

자동 갱신은 현재 처리한 일지에 반영한다. 늦게 보완한 과거 날짜는 위 명령으로 그 날짜만 다시 저장한다. 사람이 수정한 사용량 문단은 기존 편집 충돌 규칙으로 보존한다. 생성 실패 중에는 로컬 수집 내역이 먼저 남고, 성공한 처리나 사용량 전용 저장 때 위키에 반영된다.

## 보존과 한계

원장은 Git 관리 폴더의 `devlog-wiki/usage/` 아래 JSON으로 저장한다. 요청 식별자·모델·시각·수치·커밋 경계만 보관한다. 대화·추론 내용·인증 값은 원장에 넣지 않는다. 생성 CLI의 임시 출력은 사용량 추출 후 제거한다. 원장은 Git 소스 푸시에 포함되지 않으므로 비공개 백업에 포함한다.

원본 위키의 `scripts/backup_local.py`도 이 원장과 자동 편집 상태를 복사하지 않는다. 해당 상태 폴더를 별도로 보존해야 한다. 위키의 요약만으로 요청 원장을 복원할 수 없다. 중앙 저장을 설계·구현할 때만 [저장 구조 검토](../../../../docs/USAGE_STORAGE_DESIGN.md)를 읽는다. 아직 구현된 기능이 아니다.

중복 방지는 같은 로컬 원장 범위다. 여러 PC 또는 별도 작업 트리의 원장을 단순 합산하지 않는다. 원장 병합·모든 과거 기록 역수집·정확한 청구 비용 계산은 제공하지 않는다. 토큰 수를 구독 요금이나 청구액으로 바꾸지 않는다.

모델은 사용량을 계산하거나 `ai-usage` 문단을 편집하지 않는다. 별도 수동 설명이 필요하면 검증한 수치·출처·범위만 인용한다. 미수집은 0이 아니며, 코드 구현 완료를 완전한 사용량 수집으로 표현하지 않는다.
