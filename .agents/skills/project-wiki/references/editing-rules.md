# 문서 편집 기준

## 기록량과 문서 선택

기본은 당일 일지의 해당 주제만 수정한다. 작은 변경의 새 설명은 보통 2~5문장, 1~2단락이면 충분하다. 이는 목표이며 삭제 기준이 아니다. 중요한 조건·실패·결정 이유를 담으려면 늘린다. 기존 블록을 교체할 때는 앞선 별개 사실도 유지한다.

남길 것은 무엇을 바꿨는지, 왜 바꿨는지, 확인 결과와 중요한 남은 일이다. 근거 없는 이유나 빈 항목을 채우지 않는다. 일상적인 실행 과정·반복 설명·전체 파일 목록은 생략한다. 코드 세부는 커밋으로 추적한다.

| 역할 | 제목과 수정 조건 |
| --- | --- |
| daily | context.daily. 같은 날 같은 주제의 새 사실을 합친다. |
| overview | context.overview. 목적·현재 기능·중요 제약이 달라졌을 때 해당 부분만 갱신한다. |
| detail | 개요 제목 아래 `/세부 주제`. 독립적인 설명이 필요하거나 기존 설명이 틀렸을 때만 작성한다. |
| decision | `의사결정/<프로젝트>/<선택 주제>`. 이후 설계·운영에 영향을 주는 선택과 이유가 대화에 명시된 경우만 분리한다. |
| knowledge | `기술/<이름>`. 확보한 근거가 있고 별도로 다시 참고할 가치가 있을 때만 만든다. 한 번 사용했다는 이유로 만들지 않는다. |

일상 변경은 일지와 꼭 필요한 관련 문단만 고친다. 매번 소개·결정·기술 문서를 세트로 만들지 않는다. 첫 등록·방향 전환·명시적 개편에는 필요한 만큼 확장한다. 글자 수만으로 분리하지 않는다.

새 사실이 없으면 edits를 비워도 된다. 실행기는 별도의 원본 근거 영역에 입력 연결 기록을 남긴다. 이를 설명하려고 반복 문단을 만들지 않는다. 다만 새 검증 결과·실패·결정 변경은 새 사실이다. 중요 근거가 부족한 요청은 해당 항목만 deferred에 남긴다.

## 짧고 명확한 한국어

ASD-STE100의 명확성 원칙을 참고한 한국어 작성 기준이다. 영어 규격 준수·인증을 뜻하지 않는다. 영어 사전이나 단어 수 제한을 한국어에 그대로 적용하지 않는다.

- 한 문장에 한 가지 핵심을 쓴다. 같은 대상에는 같은 용어를 쓴다.
- 행위자와 동작을 분명히 쓴다. 능동문을 우선하되 모르는 행위자를 만들지 않는다.
- 조건을 먼저 쓰고 동작·결과를 잇는다. 절차는 단계당 한 동작, 일지는 사실 서술로 쓴다.
- “개선을 진행했다”보다 “중복 저장을 막았다”처럼 구체적으로 쓴다. 수식·감탄·홍보·대화체를 줄이고 `~했다/~이다`로 맞춘다.
- 계획·채택·구현·검증·배포를 구별한다. 부정·수치·단위·예외·불확실성·출처의 뜻은 줄이면서도 보존한다.

일지 첫 단락은 핵심 변화와 결과를 1~2문장, 가능하면 160자 안에 요약한다. 뒤에는 설명이 필요한 이유·실패·남은 일만 덧붙인다. 첫 단락을 다시 풀어 반복하지 않는다. 예: “같은 파일을 두 번 저장하던 오류를 수정했다. 중복 요청 테스트는 통과했다. 운영 배포는 하지 않았다.”

## 문단과 근거 보존

key는 영어 소문자·숫자·하이픈으로 된 안정적인 주제 ID다. 같은 주제는 기존 key를 재사용한다. 날짜·커밋 SHA를 key로 쓰지 않는다. sources/recent/ai-usage는 실행기 전용이다.

heading은 한국어 제목, text는 평문, links는 실제 문서 제목 배열이다. 본문에 나무마크·Markdown·HTML을 넣지 않는다. 다음에 읽을 가치가 있는 문서만 연결하되 기존 고유 근거와 관련 연결은 보존한다.

원문 인용·커밋 ID는 실행기가 접힌 근거에 남긴다. 본문에 반복하지 않는다. evidence는 보통 핵심 주장에 필요한 1~2개면 충분하며, 서로 다른 주장을 뒷받침할 근거가 필요하면 늘린다. 인용 자체는 바꾸지 않는다.

자동 영역 밖의 사람 문장을 보존한다. 사람이 고친 자동 문단은 덮어쓰지 않고 해당 수정만 보류한다. 읽기 한도에서 빠진 문서는 없는 문서가 아니다. 원문 없이 기존 내용을 추측해 바꾸지 않는다.

## 생애주기의 핵심

- 첫 등록: 무엇·누구의 문제·시작 배경·현재 범위·확인한 저장소를 짧게 소개한다. 주제에 필요한 목차만 만든다. 등록일과 실제 시작일을 구별하며 모르는 날짜·주소·역사를 만들지 않는다.
- 지속 개발: 현재 설명은 기준 브랜치의 상태, 일지는 당시 작업이다. 같은 날 후속 작업은 기존 주제에 합친다. 실패와 선택 이유를 지우지 않는다. 늦게 온 자료로 현재 설명을 과거로 되돌리지 않는다.
- 방향 전환: 이전 이유를 보존하고 이전/새 결정과 시점을 연결한다. 설계 채택과 구현 완료를 구분한다. 사실 정정만으로 새 결정을 만들지 않는다.
- 구조 개편: 상위 요약과 상세 설명을 서로 연결한다. 원문·이력·링크 보존 계획이 먼저다. 기존 제목/key를 임의로 바꾸거나 복사 후 삭제로 이동을 흉내 내지 않는다. 미지원 이동·다중 날짜 재분배·자동 채번은 보류한다.
- 중단·재개·종료: 확인한 상태와 남은 일·후속 문서를 연결한다. 과거 기록은 유지한다.

## 검증 경계

current_allowed=false이면 overview/detail은 제안하지 않는다. true여도 role=code 자료의 정확한 인용이 필요하다. 모든 편집은 1~8개 evidence를 포함한다. source는 입력 ID, quote는 해당 source.text의 연속 원문 8~800자다. decision에는 user/assistant 발언 근거가 필요하다. 커밋 제목만으로 선택 이유를 추론하지 않는다.

현재 자동 일지 날짜는 커미터 시각의 Asia/Seoul 날짜다. 실제 작업일과 다르면 확인한 작업 시점을 본문에 밝힌다. 위키 편집 이력은 개발 일지를 대신하지 않는다. ADR 번호는 자동 발급하지 않으며 기존 번호도 재사용·재정렬하지 않는다.

`excluded_blocks`의 ai-usage는 실행기가 관리하며 입력에서 생략한 문단이다. 그 표를 본문에 다시 만들지 않는다. 사용량을 설명할 필요가 있으면 sources의 검증된 수치·출처·범위만 인용한다. 합계·비용은 계산하지 않으며 부분 수집을 밝히고 미수집은 0으로 쓰지 않는다. 최신 기술 사양·배포 완료도 제공된 근거가 있어야 쓴다.
