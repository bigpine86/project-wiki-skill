# 사용량 원장과 위키 연결

2026-10-29. 사용자가 전체 구현을 승인하여 수집 보완 → 중앙 원장 → 조회 연결을 구현했다. 설명 글과 계산용 원장을 분리한다. 원장 수치로 글을 복원하거나 전체 대화를 저장하지 않는다.

## 구성

| 위치 | 역할 |
| --- | --- |
| 프로젝트 개요 | 목적·현재 구조·최근 작업, 사용량 상세 링크 |
| 날짜별 개발 기록 | 작업·이유·결과, 커밋 연결 구간의 사용량 요약 |
| 의사결정 문서 | 중요한 선택·대안·근거 |
| `/personal_usage/<project_id>` | 기간·모델·커밋 합계, 요청과 일지 연결, 수집 상태 |
| 로컬 `devlog-wiki/usage/` | 전송 전 숫자 근거, 재시도 상태 |
| 위키 DB `personal_usage` | 검증·중복 제거된 중앙 근거와 충돌 자료 |

월마다 새 문서나 메뉴를 만들지 않는다. 상세 화면 하나에 월 선택과 표를 둔다. 계산에는 모델을 호출하지 않는다. 생성 모델에는 기존처럼 관련 작업 근거만 전달하며 검증된 자동 사용량 문단은 제외한다.

## 데이터 계약과 권한

테이블 하나에 `record_key`, `project_id`, `kind`, `payload`, `conflict`, `revision`을 저장한다. SQLite는 TEXT, MySQL은 LONGTEXT다. 공통 초기화의 기존 보조 컬럼도 유지한다. JSON 함수나 별도 집계 DB를 사용하지 않는다. SHA-256 키의 고유 인덱스와 프로젝트 조회 인덱스를 둔다.

- project: 안정적인 ID와 개요 문서·프로젝트 이름의 연결. 기존 연결의 자동 변경은 거부한다.
- event: 원본 요청 ID, 출처, 세션/turn, 발생 시각, 모델, 용도, 수치. 요청 ID는 프로젝트를 넘어 중복 검사한다.
- window: 전체 커밋 SHA, 세션별 시작 경계, 종료 시각, 일지 날짜, 경계 버전 2.
- call: 고유 생성 호출 ID, 대상 기록, 모드, 완료/실패/시간 초과, 시도 번호, 수치 수집 여부.
- observation/conflict: 수집 누락·근거 충돌. 대화 원문은 포함하지 않는다.

`wiki_usage_sync`는 최대 100개 레코드를 검증한 뒤 한 트랜잭션으로 저장한다. 같은 ID와 내용은 재전송해도 바뀌지 않는다. 다른 수치·메타데이터 또는 다른 프로젝트의 같은 요청은 양쪽 모두 충돌로 표시하고 합계에서 제외한다. 충돌한 새 근거도 보존한다. 자동 병합·삭제·충돌 해소 API는 없다.

`wiki_usage_read`는 100개씩 페이지와 원장 버전을 반환한다. 여러 페이지의 버전이 다르면 조회를 다시 시작한다. 계속 변경되면 성공한 합계처럼 표시하지 않고 재시도를 요청한다. 숫자 합계는 읽을 때 계산한다.

기존 MCP 키·loopback 제한을 유지한다. API도 사이트 조회 권한과 연결된 개요의 조회/편집 ACL을 직접 검사한다. 화면은 API 결과만 표시한다. 개요 제목을 바꾸거나 권한을 관리할 때 원장 연결도 별도로 검토한다.

## 정확성 보완

이전 공통 경계에서 A 세션의 이전 시각 180, B의 120, 현재 200인 경우 B의 130→150 요청이 누락되는 사례를 재현했다. 세션별 경계로 수정했고 구형 로컬 구간을 입력 기록으로 보완한다. 요청·turn이 정확히 한 구간에 들어갈 때만 귀속한다. 경계 초과·amend 중첩은 미확인으로 둔다.

위키 생성 계획은 중앙 전송 전에 저장한다. 응답이 유실되거나 서버가 꺼져도 재시도 때문에 모델을 다시 부르지 않는다. 호출 상태는 생성 결과이며 문서 발행 결과와 다르다. 같은 ID의 메타데이터 차이도 충돌로 처리한다. 수집 확인 시각은 커밋 경계와 분리해 재점검 결과를 구별한다. 손상된 로그 항목은 누락 사유로 남기고 정상 요청을 계속 수집한다. 중앙 API는 null 수치를 0으로 바꾸지 않고 거부한다.

늦은 수집으로 달라진 기존 관리 일지는 사용량 문단만 갱신한다. 과거 문단의 목표 내용이 같으면 읽기·저장을 생략한다. 저장 응답이 유실되면 남긴 before/after 작업부터 재확인한다. 사람의 수정은 보존한다.

날짜·월 합계는 발생 시각의 Asia/Seoul 기준이다. 일지와 생성 호출 표는 커밋/기록 연결 날짜 기준이다. 캐시·추론은 총량에 다시 더하지 않는다. 여러 집계 표를 서로 합산하지 않는다.

## 백업과 복구

위키 DB 백업에 중앙 원장이 포함된다. `backup_local.py`는 Git 관리 폴더의 원장·편집 기준·대기 입력도 별도로 복사하고 SHA-256 목록을 남긴다. 활성/남은 잠금 또는 복사 중 변경이 있으면 실패한다. 다른 개발 저장소는 `--state-repo`로 명시한다. 상태 복원은 모든 해시와 경로를 검증한 후 빈 대상에만 허용한다.

서버와 편집 작업을 멈추고 백업한다. DB와 편집 기준은 같은 시점의 사본을 복원한다. 대화 자료나 키가 포함될 수 있는 비공개 백업을 소스 저장소에 올리지 않는다. Git bundle은 커밋된 소스만 포함한다.

## 검증과 남은 범위

회귀 검사에는 세션별 경계, 지연 요청, 중첩 구간, 부분 수집, 호출 상태, 메타데이터 충돌, 백업 복원·변조 검출, 중앙 응답 유실, 생성 계획 재사용, 과거 요약 갱신, 사람 수정 보존을 포함한다. Go 검사는 원장 중복·프로젝트 간 충돌·입력 검증·배치 원자성·페이지·기간 집계·ACL과 화면을 검증한다.

자동 수집은 지원 로그에서 관측한 부분 합계다. 중앙 중복 검사는 구현했지만 여러 PC의 원격 연결 설정과 자동 전송 서비스는 제공하지 않는다. 전체 과거 자료 역수집, 토큰의 청구액 환산, 프로젝트 이름 변경/원장 충돌 해소는 별도 작업이다. MySQL은 공통 자료형·SQL 경로를 검토하며 실제 서버 검증 여부는 작업 결과에 명시한다.
